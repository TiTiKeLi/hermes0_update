# 并行分派智能体

## 概述

面对多个独立的失败/任务/问题域时，逐一处理浪费时间。每个排查/开发是独立的，可以并行进行。

**核心原则：** 每个独立问题域分派一个智能体，让它们并发工作。

**工具入口：** `delegate_task(tasks=[...])` — Heremes 内置的批量子智能体 API。

---

## 1. 边界条件

### 入口条件（必须全部满足）
- [ ] 存在 2 个以上的独立工作流
- [ ] 每个工作流无需其他工作流的上下文即可理解
- [ ] 工作流之间无共享状态（不读写同一文件、不依赖同一变量）
- [ ] 每个工作流有明确的完成标准

### 跳过条件（一条即跳过）
- [ ] 只有一个任务 → 直接做，不需要分派
- [ ] 任务是顺序依赖的（B 依赖 A 的结果）→ 顺序执行
- [ ] 任务共享同一状态/文件 → 合并为单个子智能体
- [ ] 任务需要用户交互/澄清 → 不能分派给子智能体

### 中止条件（执行中，一条即停）
- [ ] 子智能体返回错误提示需要更多上下文 → 重新构造后补发
- [ ] 连续 2 个子智能体因相同原因失败 → 切换为手动处理
- [ ] 用户插入新指令 → 取消未完成子智能体

---

## 2. 决策矩阵

| 场景 | 行动 | 工具链 | 产出 |
|------|------|--------|------|
| 多个独立测试失败 | 每个测试文件分派一个智能体 | `delegate_task(batch)` | 每个失败的根因分析 |
| 多个子系统独立故障 | 每个子系统分派一个智能体 | `delegate_task(batch)` | 每个子系统的诊断报告 |
| 多文件并行重构 | 每个重构单元分派一个智能体 | `delegate_task(batch)` | 每个文件的重构结果 |
| 独立需求并行实现 | 每个需求分派一个智能体 | `delegate_task(batch)` | 每个功能的实现 |
| 有顺序依赖 | 不能并行！改为顺序执行或 chain | 普通工具调用 | 顺序执行输出 |

## 3. 原子步骤

### Step 1: 识别独立性问题域

**输入**：当前问题集合（测试失败列表、Bug 清单、需求列表）
**操作**：
1. 列出所有待处理事项
2. 两两之间问：A 修复后 B 是否自动解决？→ 如果是，B 不独立，合并入 A
3. 问：A 和 B 是否读写同一文件/状态？→ 如果是，不独立
4. 标记：独立 ✓ / 不独立 ✗

### Step 2: 构造分批并行任务

**输入**：独立性标记表
**操作**：
1. 对每个独立任务，构造：
   - **goal**: 一句话目标（如"定位 test_user_auth.py 失败的根因"）
   - **context**: 完整上下文——文件路径、错误信息、环境说明
     - ⚠️ 子智能体不知道你的会话历史！**所有关键信息必须在 context 中提供**
     - 包含：文件路径、关键代码段、错误输出、约束条件
2. 打包为 `tasks` 数组：
   ```python
   delegate_task(tasks=[
       {"goal": "诊断 test_X.py 失败", "context": "路径: tests/test_X.py\n错误: ..."},
       {"goal": "诊断 test_Y.py 失败", "context": "路径: tests/test_Y.py\n错误: ..."},
   ])
   ```

### Step 3: 等待结果并汇总

**输入**：subagent 逐步返回的结果
**操作**：
1. 每个子智能体完成时结果自动进入会话
2. 读完所有结果后：
   - 归类：成功/失败/需要更多上下文
   - 如果有共通模式 → 汇总
   - 如果有冲突结论 → 需要手动判断

### Step 4: 决定后续动作

**输入**：子智能体结果汇总
**操作**：
1. 所有成功 → 向用户报告完整结果
2. 部分失败 → 手动处理失败的子智能体（或重新构造 context）
3. 所有失败 → 切换策略，可能：
   - 需要更多上下文
   - 任务本身不可并行（假独立）
   - 环境问题（网络/权限）

**验证**：
```
每个分发的子智能体都有结果返回（成功或失败）
对失败的子智能体有明确的后续行动
```

## 5. 反馈回路

### ⚠️ 子智能体陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| **上下文不足** | 智能体问"请提供更多信息" | context 中提供完整错误输出+文件路径+环境版本 |
| **共享文件冲突** | 两个智能体同时编辑同一文件 | 分配不同文件，或设置工作目录隔离 |
| **认知过载** | 子智能体 task list 任务描述太长导致理解偏差 | goal 一句话，context 关键信息，不要塞无关历史 |
| **结果验证** | 子智能体声称"已完成"但没证据 | 在 context 中要求：返回确切的 exit code / 输出摘要 |

### 子智能体 context 模板

```python
# 最小必要 context 模板
context = f"""
## 环境
- 文件路径: tests/test_login.py
- 相关文件: src/auth/login.py, src/auth/session.py

## 问题
测试 test_login_failed 失败:
错误信息:
{error_output}

## 约束
- 不要修改 src/ 下的代码
- 只分析根因，不修复
- 返回：根因 + 证据行号
"""
```
