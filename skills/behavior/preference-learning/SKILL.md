# Preference Learning — 用户偏好学习 v1

## 核心问题

USER.md 是静态的，不会随交互而进化。用户的偏好、工作习惯、常用模式在一次会话中被表述后，下次会话又得重新说。

## 偏好类别

### 1. 显式偏好（用户明确说的）

| 类型 | 例子 | 写入位置 |
|------|------|---------|
| 输出格式 | "用表格","别太长","要详细" | USER.md |
| 语言风格 | "说中文","专业术语用英文" | USER.md |
| 优先级偏好 | "先搞定这个再管别的" | task-prioritization |
| 工具偏好 | "用 Python 别用 Shell" | 临时记忆 |

### 2. 隐式模式（从行为推断）

| 模式 | 推断方法 |
|------|---------|
| 常用时间 | 何时发起对话（工作时间 vs 非工作时间） |
| 重复请求 | 多次问同样类别的问题 → 可以创建 skill |
| 修正模式 | 用户反复修正同一类型的错误 → 提示用户是否需要固化规则 |
| 跳过模式 | 用户总是跳过某些步骤 → 可以自动化 |

### 3. 反模式（用户明确不喜欢的）

```
□ "不要联网" → 记录为限制条件
□ "别用那个工具" → 记录为禁用项
□ "太慢了" → 记录为性能期望
```

## 学习流程

```
用户交互
  ↓
检测到偏好信号
  ├── 显式: "我喜欢..." / "我不喜欢..."
  ├── 隐式: 第 3 次类似行为 → 建议记录
  └── 反模式: "别..." / "不要..."
  ↓
确认（memory-confirmation-feedback 风格）
  └── "我注意到你经常... 要不要记下来？"
  ↓
更新 USER.md
  └── 追加新的偏好条目
```

## USER.md 更新格式

```markdown
## Learned Preferences（自动学习）

- [2026-07-25] 偏好简洁输出，表格优先于段落（从交互推断）
- [2026-07-25] 修复网络问题时优先检查 NO_PROXY（用户反复处理此问题）
```

## 适用场景

### 入口条件

- 用户明确表达了偏好
 - 检测到 3 次以上重复行为模式
 - 用户修正了输出方式
 - 会话总结阶段

### 出口条件

- 偏好已更新到 USER.md
 - 用户确认了变更（如果走确认流程）
 - 反模式已记录为约束条件
 - 无需更新的情况已忽略
