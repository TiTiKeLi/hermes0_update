# Caveman 模式（小模型双向约束）

## 为什么需要 caveman

3B 小模型无法处理开放性问题。给它的任务必须是**不需要动脑子的活**。

| 任务类型 | 3B 表现 |
|---------|---------|
| 「压缩到 1500 字符，保留关键信息」 | ❌ 输出 43 字符 = 标题区就停了 |
| 「每行判断类型，prose 行转 id 格式」 | ✅ 正确转换，省 44% 空间 |
| 输出 prose 回复 | ❌ thinking 链吞掉 80%+ 预算 |
| 输出 `> 阶段:结果 · **结论:一句话**` | ✅ 精准，无废话 |

**原理**：把「理解→总结→压缩」降级为「**分类→删留→重写**」——每行独立判断，不跨行推理。

---

## 第一部分：输入侧（Caveman Compress — Prompt 指令构造）

给小模型写 prompt 的规则，适用场景：记忆压缩、日志分级、消息预分类。

### 核心参数

| 参数 | 值 | 原因 |
|------|----|------|
| temperature | **0.05** | 接近贪婪解码，3B 不会发散 |
| max_tokens | 1024 | 15 行输入约需 600+ token 输出 |
| system prompt | 见下 | 只给规则 + 例子，不给思考空间 |
| 批次大小 | **≤15 行** | 超 15 行时 thinking 链吃掉全部输出预算 |

### 指令模板

```
系统提示（必须包含）：
1. 描述「你只做一种转换」
2. 每条规则一个独立判断（if → then 格式）
3. 至少 2 个具体例子（1 个转换行 + 1 个保留行）
4. 禁止词：「不思考」「不解释」「不总结」
5. 结尾：「只输出行。不解释。」
```

#### 示例：prose→id 转换

```
你只做一种转换：把"- 描述文字 (id:N [tag])" 转成 "id:N [tag] 精简值"

规则：
- 行以 "id:" 开头 → 保留原样
- 行以 "- " 开头，包含 (id:N [tag]) → 提取为 id:N [tag] + 精简描述
  例: "- 用户偏好中文回复简洁 (id:6 [pref])" → "id:6 [pref] 中文·简洁"
  例: "- LLM通过host.docker.internal访问 (id:3 [ollama])" → "id:3 [ollama] host.docker.internal:11434"
- 行以 "##" 或 "# " 开头 → 保留原样
- 空行或 "§" → 保留
- 其他行 → 保留原样

精简值的规则：从描述中提取关键信息，去掉虚词。
输出：只输出行。不解释。
```

### 输出检查清单

每次调完小模型必须检查：
- [ ] 输出没有完整自然语言句子
- [ ] 每行是一个独立事实/条目
- [ ] 输出行数 ≈ 输入中有效行数（没丢太多）
- [ ] 没有「总结如下」「以下是输出」等元语言
- [ ] 没有 /think 或 thinking 前缀污染
- [ ] 行格式和规则一致（id:N [tag] 格式正确）

### 验证模式

永远先在小输入上测试，再放大：
```python
# 1. 构造 4-5 行测试输入（含 2 行转换目标 + 2 行保留目标）
# 2. 调模型，temperature=0.05
# 3. 检查格式正确性
# 4. 放大到全量输入
# 5. 用回退机制兜底（模型失败时有确定性 fallback）
```

### 两阶段架构

当任务需要确定性兜底时：
```
阶段1: VibeThinker caveman 清洗（prose→id 转换）
  大输入时按 15 行分批调用
  每批独立调模型
  失败时保留该批原文

阶段2: 确定性算法回退
  模型清洗后可能超出限制 → 按规则截断
  模型失败时 → 完全确定性处理

输出标签:
  [3B]        = 阶段1 成功，无需阶段2
  [暴力]       = 阶段1 失败，纯阶段2
  [3B+暴力]    = 两阶段都参与了
```

### 已使用场景

| 场景 | 说明 |
|------|------|
| 记忆压缩 | prose→id 清洗 + 截断，cron 每 5 分钟 |
| 回复格式 | sub-agent 自身输出格式，同理念不同域 |
| 日志分级 | 提取日志行→fatal/error/warn/info |
| 消息预分类 | 用户消息→chat/task/research_request |

## 第二部分：输出侧（Caveman Reply — 3B Sub-Agent 回复格式）

⚠️ **仅对 VibeThinker-3B sub-agent 生效**，主模型（DeepSeek v4）不受此限制，正常自然语言回复。

### 输出规则

1. 只输出 2 部分：**阶段性成果** · **结论**
2. 无 prose、无解释、无过渡句
3. 阶段性成果用 `>` 标记，结论用 `**` 标记
4. 单条不超过 80 字符

### 格式

```
> 阶段:结果1·结果2·结果3

**结论:一句话**
```

### 示例

**错误场景**：模型不支持图片输入，WeChat 传来 JPG 文件

- 原始回复（禁用）：`ERROR: Cannot read "xxx.jpg" ... Inform the user...`
- Caveman（启用）：
  ```
  > 图片过滤:1条已跳过·模型VibeThinker-3B仅文本
  **结论:确认忽略图片请求**
  ```

### 触发条件

加载会话时自动激活。所有回复生效，包括错误、确认、结果。

## 第三部分：tirith 拦截提醒（仅限终端命令）

含 `http://` 的终端命令会被 Tirith 拦截。小模型调用必须通过 `.py` 脚本用 urllib，不可用内联 `python -c`。

---

## Pitfalls

1. **Thinking 链吞噬预算**：3B 模型会输出超长 thinking trace，消耗 80%+ token 预算。必须在 system prompt 写「不思考」。
2. **"精简值"字面量问题**：prompt 里的示例格式会被模型当成字面模板复制。确保例子里的值不是占位符。
3. **批次不宜过大**：15 行/批是上限。超限后模型输出截断在中间。
4. **第一次加载慢**：3B 模型首次调用需 8-13s 加载，后续 4-6s。首次超时正常。
5. **Tirith 拦截**：含 `http://` 的终端命令被拦截。小模型调用必须通过 `.py` 脚本用 urllib，不可用内联 `python -c`。
